# SigNoz pages, without a backend

Every story here is a real SigNoz page: the app's own provider tree, the real
`AppLayout` with its side nav and banners, and msw answering every request. No
backend, no seeded database, no login.

What that buys you:

- a page in a state that is hard to reach against a live backend (empty
  workspace, expired license, a viewer's permissions, an endpoint that fails);
- a state you can link to, so a bug report can point at it;
- design and a11y review of a page without waiting on data.

## Finding a page

The sidebar mirrors the app's own side nav, so a page sits where you would click
it in the product. `Alerts`, `Dashboards`, `Services`, `Logs`, `Traces` and the
rest come first, then `Settings`, then `Auth` and `System` for the pages you
reach by accident rather than on purpose.

A page that is one route with several tabs is one story per tab, under the
module: `Logs / Explorer`, `Logs / Pipelines`, `Logs / Saved Views`. Every tab
renders the module page, so the tab strip is there either way; the story decides
which tab is open.

## Reading a story

Three things drive what you see, and none of them is a prop:

- **Controls panel.** Every knob is a knob on a response. Turning one
  re-registers the msw handlers and remounts the page with an empty query cache,
  so the page fetches again. `Data` (loaded, loading, error) and `Access` are on
  every story; the rest belong to the page.
- **Theme toolbar.** Dark and light, the same classes and tokens the app sets at
  boot.
- **The story itself.** A named state worth linking to, `Default` first. Anything
  reachable by turning a knob is a control, not a story.

`⌘K` works inside a story, dev tools included: **AuthZ DevTools** lists the
permissions the page actually checked and overrides them one at a time.

## Adding one

The `signoz-page-story` skill in `.claude/skills/` carries the workflow, and
`src/storybook/README.md` is the harness it runs on: the runtime, the controls,
the access model, the module mocks and the navigation containment.
